# แล็บ 11.2: ต่อ Ollama เข้ากับเซิร์ฟเวอร์ MCP ค้นเว็บ (แฮนด์ออน)

สัปดาห์ที่ 11 เราเขียนเซิร์ฟเวอร์ MCP แล้วทดสอบด้วยมือ แล็บนี้เติมชิ้นสุดท้าย
คือ **ไคลเอนต์** ที่ทำให้โมเดลบนเครื่องของคุณใช้เครื่องมือนั้นได้เอง
จบแล็บนี้คุณจะมีผู้ช่วยค้นเว็บที่รันบนเครื่องตัวเองทั้งหมด **ไม่ต้องมี API key สักตัว**

```
  Ollama (qwen3:8b)          agent.py                 server.py
  พูดภาษา OpenAI tools  <->  ล่ามแปลสคีมา      <->   พูด JSON-RPC บน stdio
                                                          |
                                                    search_tools.py
                                                          |
                                                    DuckDuckGo + หน้าเว็บจริง
```

| ไฟล์ | หน้าที่ |
| --- | --- |
| `search_tools.py` | ตรรกะล้วน ไม่ import `mcp` ทดสอบได้ด้วย Python ธรรมดา |
| `server.py` | ชั้นโปรโตคอลบาง ๆ เอาฟังก์ชันไปลงทะเบียนเป็น MCP tools |
| `agent.py` | ไคลเอนต์ MCP + ลูปเอเจนต์ที่ขับโมเดล |

## เตรียมเครื่อง

```bash
ollama pull qwen3:8b          # แรมน้อยใช้ qwen3:4b
pip install "mcp[cli]"
cd labs/w11_2_web_search
```

ต้องมีอินเทอร์เน็ตเฉพาะตอนค้นจริง (ขั้นที่ 2 กับ 4) ขั้นอื่นรันออฟไลน์ได้หมด

## ขั้นที่ 1: ทดสอบเครื่องมือโดยยังไม่ยุ่งกับ MCP

```bash
python search_tools.py
```

คาดว่าจะได้ `OK: search_tools self-check ผ่าน (แกะผล, ถอด HTML, ด่านกัน SSRF)`

**เปิด `search_tools.py` อ่านก่อนไปต่อ** สิ่งที่ต้องสังเกตมี 3 อย่าง

1. `parse_results` เป็นฟังก์ชันบริสุทธิ์ จึงทดสอบด้วย HTML ตัวอย่างที่ฝังไว้ได้
   โดยไม่ต้องต่อเน็ต วันที่ DuckDuckGo เปลี่ยนหน้าเว็บ เราจะรู้ทันทีว่าพังที่ไหน
2. `_check_url` กัน **SSRF** เครื่องมือที่รับ URL จากผลการค้นเท่ากับให้คนอื่น
   สั่งได้ว่าจะยิงไปที่ไหน ถ้าไม่กัน โมเดลจะถูกหลอกให้ไปอ่าน
   `http://localhost:11434` (Ollama ของคุณเอง) หรือ `http://169.254.169.254`
   (metadata ของคลาวด์ ซึ่งคืนคีย์ออกมา) ได้
3. `fetch_page` ห่อเนื้อหาไว้ใน `<untrusted_web_content>` เสมอ
   เพื่อให้โมเดลแยกออกว่าส่วนไหนคนอื่นเขียน

ค้นจริงหนึ่งครั้ง

```bash
python search_tools.py --live "Model Context Protocol specification"
```

**นี่คือสิ่งเดียวที่โมเดลเห็นตอนตัดสินใจว่าจะเรียกเครื่องมือไหน**

## ขั้นที่ 3: ทดสอบท่อทั้งเส้นโดยยังไม่ใช้โมเดล

```bash
python agent.py --self-check
```

ขั้นนี้ใช้โมเดลจำลองที่สั่งให้ดึง `http://127.0.0.1:11434/` ถ้าด่านกัน SSRF
ทำงาน เอเจนต์จะได้ข้อความปฏิเสธกลับไปแล้วจบงานอย่างสุภาพ

สิ่งที่การทดสอบนี้พิสูจน์: จับมือ (initialize + notifications/initialized),
`tools/list`, การแปลสคีมา MCP เป็นรูปแบบของฝั่งโมเดล, การเรียกเครื่องมือ,
การส่งผลกลับเข้าบทสนทนา และการเรียกเครื่องมือที่ไม่มีจริงต้องได้ `isError`
ไม่ใช่เซิร์ฟเวอร์ตาย

> **จุดที่ต่างจากสัปดาห์ที่ 11** มินิเซิร์ฟเวอร์ที่เราเขียนเองตอบทุกคำขอทันที
> แต่เซิร์ฟเวอร์จริงจะไม่ยอมทำงานจนกว่าไคลเอนต์จะส่ง `notifications/initialized`
> ดูเมท็อด `handshake` ใน `agent.py`

## ขั้นที่ 4: ถามจริงด้วยโมเดลบนเครื่อง

```bash
python agent.py "Model Context Protocol เวอร์ชันล่าสุดคือวันที่เท่าไร"
```

`agent.py` พิมพ์ร่องรอยการทำงานลง stderr ส่วนคำตอบลง stdout จึงแยกเก็บได้

```
  [1] เรียก search_web({'query': 'Model Context Protocol latest version', 'k': 5})
      -> ผลการค้น 5 รายการ ...
```

**สังเกตให้ดี:** ตอนทดสอบ qwen3:8b มักเรียก `search_web` แล้วตอบเลย
โดย **ไม่เรียก `fetch_page`** ทั้งที่พรอมป์ตระบบสั่งให้เปิดหน้าจริงก่อน
นั่นแปลว่ามันสรุปจากข้อความย่อของผลการค้นเท่านั้น ซึ่งเสี่ยงผิด
ข้อ 2 ของแบบฝึกหัดให้แก้เรื่องนี้

ถ้าเครื่องรันโมเดลเองไม่ไหว สลับไปรุ่นฟรีได้โดยไม่ต้องแก้โค้ด

```bash
python agent.py "..." --provider openrouter
```

## ขั้นที่ 5: การทดลอง prompt injection

เครื่องมือค้นเว็บเปิดช่องให้ **คนที่เขียนหน้าเว็บ** พิมพ์ข้อความเข้าไปในบริบทของ
โมเดลคุณได้โดยตรง ขั้นนี้วัดว่าโมเดลของคุณทนแค่ไหน

```bash
python agent.py --injection-test
```

มันจะรันคำถามเดียวกันสองรอบด้วยหน้าเว็บที่วางยาชุดเดียวกัน
ต่างกันแค่พรอมป์ตระบบ (มีกับไม่มีกติกาความปลอดภัย) แล้วรายงานสองค่า
คือ **ทำตามคำสั่งแฝงไหม** และ **รายงานว่าเจอคำสั่งแฝงไหม**

ผลที่ผู้สอนได้ตอนเตรียมแล็บ (ผลของคุณอาจต่างออกไป ให้จดของจริงลงรายงาน)

| โมเดล | ไม่มีกติกา | มีกติกา |
| --- | --- | --- |
| `qwen3:8b` บนเครื่อง | ทำตามคำสั่งแฝง | **ยังทำตามอยู่** |
| รุ่นฟรีตัวใหญ่ผ่าน OpenRouter | ไม่ทำตาม | ไม่ทำตาม และรายงานว่าเจอ |

ข้อสรุปที่ต้องจำ: **พรอมป์ตระบบช่วยได้ แต่ไม่ใช่กำแพง** โมเดลเล็กยอมทำตาม
คำสั่งแฝงง่ายมาก การป้องกันจริงจึงต้องอยู่ที่สถาปัตยกรรม คือ
ให้สิทธิ์น้อยที่สุด ไม่มีเครื่องมือที่ทำลายอะไรได้ และให้คนอนุมัติสิ่งที่ย้อนกลับไม่ได้
(สัปดาห์ที่ 12 และ 14)

> ฟังก์ชัน `verdict` ใน `agent.py` มีคอมเมนต์เล่าว่าตัววัดรุ่นแรกของแล็บนี้
> **ตัดสินผิด** เพราะนับโมเดลที่ทำถูก (รายงานว่าเจอคำสั่งแฝง โดยยกข้อความนั้นมาอ้าง)
> ว่าโดนยึด บทเรียนคือตัววัดเองก็ต้องมีการทดสอบ

## แบบฝึกหัด

1. เพิ่มเครื่องมือ `fetch_pdf` หรือ `search_scholar` อีก 1 ตัวใน `search_tools.py`
   พร้อม self-check ใน `_self_check`
2. แก้ให้โมเดล **เปิดหน้าจริงก่อนตอบเสมอ** ลองสองวิธีแล้วเทียบกัน
   (ก) แก้ `description` ของ `search_web` ให้บอกชัดว่าผลลัพธ์ยังไม่ใช่คำตอบ
   (ข) บังคับในโค้ด `run` ว่าห้ามจบถ้ายังไม่เคยเรียก `fetch_page`
   วิธีไหนได้ผลกว่า และแลกกับอะไร
3. วัดอัตราการอ้างอิง: ตั้งคำถาม 10 ข้อ แล้วนับว่ากี่ข้อที่คำตอบมี URL
   ซึ่ง **ปรากฏจริงในผลการค้น** (โมเดลชอบแต่ง URL ที่ดูสมเหตุสมผล)
4. รัน `--injection-test` กับโมเดลอย่างน้อย 3 ตัว แล้วทำตารางเทียบ
5. `_check_url` ยังมีช่องโหว่ **TOCTOU** คือมันตรวจ IP ตอนหนึ่ง แต่ `urlopen`
   ไปต่อ DNS อีกทีตอนหนึ่ง เซิร์ฟเวอร์ที่ตอบ DNS ต่างกันสองครั้ง
   (DNS rebinding) ยังเล็ดลอดได้ ให้เสนอวิธีอุดมา 1 วิธี ไม่ต้องเขียนโค้ด

**ส่งงาน:** โค้ดที่แก้แล้ว, ร่องรอยการทำงาน 3 คำถาม, ตารางผลข้อ 4
และคำตอบข้อ 5

## ปัญหาที่พบบ่อย

| อาการ | สาเหตุและทางแก้ |
| --- | --- |
| `เซิร์ฟเวอร์ปิดไปก่อนตอบ initialize` | รัน `python server.py` ตรง ๆ เพื่อดู error ส่วนใหญ่คือยังไม่ได้ `pip install "mcp[cli]"` |
| `No module named 'mcp.server.fastmcp'` | แพ็กเกจ `mcp` ขึ้นเวอร์ชัน 2 แล้วเปลี่ยนชื่อคลาสเป็น `MCPServer` ตัว `server.py` ของแล็บนี้รองรับทั้งสองเวอร์ชันอยู่แล้ว ถ้าเจอที่ไฟล์อื่นให้ลงเวอร์ชัน 1 ด้วย `pip install "mcp[cli]<2"` |
| ค้นแล้วได้ HTTP 202 หรือ 429 | ถูกจำกัดอัตรา ทั้งห้องยิงพร้อมกันจาก IP เดียวกัน ให้รอสักครู่ `search_web` เว้นจังหวะให้ 2 วินาทีต่อคำขออยู่แล้ว |
| `No endpoints found that support tool use` | โมเดลรุ่นฟรีที่เลือกไม่มี endpoint ที่รองรับ tool calling ในตอนนั้น ให้ดูตัวที่รองรับด้วย `python ../llm.py --free --tools` |
| โมเดลไม่ยอมเรียกเครื่องมือเลย | โมเดลเล็กเกินไปหรือไม่มีเทมเพลตเรียกเครื่องมือ ลอง `qwen3:8b` ขึ้นไป |
| ตอบช้ามาก | โมเดลบนเครื่องคิดทีละโทเคน ลด `--max-steps` หรือใช้ `qwen3:4b` |

## ข้อจำกัดที่ต้องรู้ และมารยาท

แล็บนี้ **แกะ HTML ของหน้าผลการค้น** ซึ่งเหมาะกับการเรียนในห้องเท่านั้น
ระบบที่ใช้งานจริงควรใช้ search API ที่มีสัญญารองรับ (Brave, Tavily, SearXNG
ที่คุณโฮสต์เอง) เพราะโครงสร้างหน้าเว็บเปลี่ยนเมื่อไรก็ได้ และการยิงถี่เกินไป
เป็นการเบียดเบียนบริการของคนอื่น

- เว้นจังหวะอย่างน้อย 2 วินาทีต่อคำขอ (`MIN_INTERVAL` ในโค้ด)
- ประกาศตัวตนที่ชัดเจนใน User-Agent
- อย่ารันลูปค้นทิ้งไว้โดยไม่มีเพดาน

## ต่อเซิร์ฟเวอร์นี้เข้ากับไคลเอนต์อื่น

`server.py` เป็นเซิร์ฟเวอร์ MCP มาตรฐาน จึงต่อเข้ากับ Claude Desktop,
Claude Code, Gemini CLI หรือไคลเอนต์ตัวไหนก็ได้ด้วยไฟล์ตั้งค่าแบบเดียว
กับที่ใช้ในสัปดาห์ที่ 11 (ดู [`../w11_server/README.md`](../w11_server/README.md))
เปลี่ยนแค่พาธให้ชี้มาที่ไดเรกทอรีนี้

```json
{
  "mcpServers": {
    "web-search": {
      "command": "python",
      "args": ["/ABS/PATH/labs/w11_2_web_search/server.py"]
    }
  }
}
```

นี่คือประเด็นหลักของ MCP ทั้งสัปดาห์: **เขียนเซิร์ฟเวอร์ครั้งเดียว ใช้ได้กับ
โมเดลและไคลเอนต์ทุกตัว** ตั้งแต่ qwen3 บนเครื่องตัวเองไปจนถึงผู้ช่วยเชิงพาณิชย์
