# แล็บสัปดาห์ที่ 13: Harness, Skills และ Plugins

ปลั๊กอินตัวอย่างที่ครบทั้ง 4 กลไกขยายความสามารถ ใช้เป็นแม่แบบสำหรับงานของคุณเอง

```
w13_skills_plugin/
  eval_skill.py                  วัดว่า description ทำให้ skill ถูกเรียกถูกจังหวะไหม
  plugin/
    .claude-plugin/plugin.json   ข้อมูลแพ็กเกจ
    skills/lab-report/
      SKILL.md                   ระดับที่ 2: ขั้นตอนการทำงาน
      reference/rubric.md        ระดับที่ 3: รายละเอียด อ่านเมื่อจำเป็น
      scripts/check_report.py    ระดับที่ 3: งานที่ตรวจด้วยกฎได้ ให้โปรแกรมทำ
    commands/lab-check.md        คำสั่งลัด /lab-check
    hooks/hooks.json             กฎอัตโนมัติ
    hooks/block_secrets.py       บล็อกคำสั่งที่จะทำให้ API key หลุด
```

## แนวคิดหลัก: การเปิดเผยแบบขั้นบันได

| ระดับ | อยู่ที่ไหน | โหลดเมื่อไร | ขนาด |
| --- | --- | --- | --- |
| 1 | `name` + `description` ใน frontmatter | อยู่ในบริบทเสมอ | ~30 โทเคน |
| 2 | เนื้อหาของ `SKILL.md` | เมื่อโมเดลเห็นว่างานตรงกับ description | ~300 โทเคน |
| 3 | `reference/`, `scripts/` | เมื่อ `SKILL.md` บอกให้อ่านหรือรัน | ไม่จำกัด |

ผลลัพธ์: ความรู้เฉพาะทางที่ละเอียดเท่าไรก็ได้ โดยไม่กินบริบทตอนที่ไม่ได้ใช้

## รันเดี๋ยวนี้ (ไม่ต้องติดตั้งอะไร)

```bash
# ตรรกะของ skill ทำงานถูกต้องไหม
python plugin/skills/lab-report/scripts/check_report.py

# hook บล็อกคำสั่งอันตรายได้จริงไหม
python plugin/hooks/block_secrets.py --self-check
echo '{"tool_input":{"command":"cat .env"}}' | python plugin/hooks/block_secrets.py

# description ทำให้ skill ถูกเรียกถูกจังหวะไหม
python eval_skill.py --self-check
```

## รันกับโมเดลจริง

```bash
ollama pull qwen3:8b
python eval_skill.py --model qwen3:8b
```

ถ้า accuracy ต่ำ ให้ดูว่าผิดทางไหน

- **false negative** (ควรเรียกแต่ไม่เรียก): description แคบหรือกำกวมเกินไป
  เพิ่มคำที่ผู้ใช้พูดจริง เช่น "ตรวจก่อนส่ง", "พร้อมส่งหรือยัง"
- **false positive** (เรียกทั้งที่ไม่ควร): description กว้างเกินไป
  เพิ่มประโยค "ห้ามใช้กับ ..." ให้ชัด

แก้ `SKILL.md` แล้วรันซ้ำ **นี่คือลูป evaluator-optimizer จากสัปดาห์ที่ 14 ที่ใช้กับตัวเอง**

## ติดตั้งเข้ากับ harness

รูปแบบไฟล์ต่างกันไปตามเครื่องมือ แต่แนวคิดเหมือนกันหมด:
โฟลเดอร์ของคำสั่งที่โหลดตามต้องการ

| Harness | วิธี |
| --- | --- |
| Claude Code | คัดลอก `plugin/skills/lab-report/` ไปที่ `.claude/skills/` ของโปรเจกต์ |
| harness อื่น | ดูเอกสารของเครื่องมือนั้นเรื่องไฟล์คำสั่ง (`AGENTS.md`) และการโหลดคำสั่งตามต้องการ |

`AGENTS.md` เป็นข้อตกลงกลางที่เครื่องมือหลายค่ายอ่านได้ ถ้าอยากให้กติกามีผลกับทุกเครื่องมือ
ให้เขียนไว้ที่นั่น

## เลือกกลไกให้ถูก

| คำถาม | ถ้าใช่ |
| --- | --- |
| ต้องใช้ทุกครั้งในโปรเจกต์นี้ไหม | ไฟล์คำสั่งโปรเจกต์ (`AGENTS.md`, `CLAUDE.md`) |
| ต้องเชื่อมกับระบบภายนอกไหม | MCP server (สัปดาห์ที่ 11) |
| ต้องเกิดขึ้นแน่นอนโดยไม่พึ่งดุลพินิจโมเดลไหม | Hook |
| ผู้ใช้เป็นคนเริ่มเองเสมอไหม | คำสั่งลัด |
| นอกจากนั้น | Skill |

## งานที่ต้องส่ง

1. เขียน Skill ของคุณเอง 1 ชุดสำหรับงานเฉพาะทางในสาขาของคุณ
   ต้องมี `SKILL.md` + ไฟล์อ้างอิงอย่างน้อย 1 ไฟล์ + สคริปต์ที่รันได้ 1 ตัวพร้อม self-check
2. เขียนชุดทดสอบ 10 คำขอใน `eval_skill.py` (ควรเรียก 5 ไม่ควรเรียก 5)
3. รันวัด แก้ `description` แล้ววัดซ้ำ **ส่งตารางคะแนนก่อนและหลัง**
4. รวมเป็น plugin ที่มีคำสั่งลัด 1 คำสั่งและ hook 1 ตัว
5. รัน skill เดียวกันใน harness 2 ตัวที่ต่างกัน บันทึกว่าอะไรพกพาได้และอะไรไม่ได้
